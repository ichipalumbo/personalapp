## 3. Status dos itens 1 a 3

- 1. Feito — adicionei snapshot e rollback do array `compromisso.excecoes` no `catch` do `btnReagendarInstancia`, sem tocar em `excecoesDetalhadas` nem no caminho de sucesso.
- 2. Feito — deixei comentário no `catch` avisando que a reposição remota permanece ativa no servidor após o rollback local.
- 3. Parou — não fiz teste automatizado para esse handler porque o código está acoplado ao DOM global (`window`, `aulas`, `obterCompromissoSelecionado`, callback modal) e qualquer cobertura confiável exigiria extrair a lógica para módulo/testável, o que seria refatoração fora de escopo.

## 4. Campos mutados e rollback

O handler de `btnReagendarInstancia` muta apenas o campo `compromisso.excecoes` neste fluxo:

- `if (!compromisso.excecoes) compromisso.excecoes = [];`
- `compromisso.excecoes.push(dataAlvoStr);`

O rollback restaura o estado anterior com:

```js
if (_mutouExcecoes) {
    compromisso.excecoes = [...(_snapshot.excecoes || [])];
}
```

Não há mutação de `excecoesDetalhadas` nesse trecho; a outra mutação de `excecoesDetalhadas` que aparece na edição não faz parte do handler de reagendamento da instância.

## 5. Confirmação da reposição remota

A reposição já foi criada no servidor antes do `salvarDados(true)`. Isso significa que o rollback local reverte a aula na agenda, mas não apaga o registro remoto. Essa honestidade ficou explícita no código no `catch` do handler:

```js
// Reposição remota permanece criada no servidor; o rollback reverte somente a aula na agenda local.
```

O impacto é parcial: a usuária vê a aula de volta na agenda, mas a reposição remota continua persistida e exigiria uma rota de delete em outra rodada.

## 6. Cobertura de teste

Teste não realizado.

Motivo: o handler está dentro de um listener de DOM com estado global (`window`, `aulas`, `obterCompromissoSelecionado` e callback do modal), sem módulo exportável para injetar um `compromisso` controlado e forçar `salvarDados` a falhar. Para cobrir de forma confiável, seria necessário extrair a lógica do callback para um módulo/funcionalidade testável, ou montar um ambiente DOM/JS completo que o projeto não possui.

O que seria necessário para cobrir de verdade:
- extrair o corpo do `click`/callback para uma função explícita e isolada;
- injetar `compromisso`, `salvarDados`, e a falha de persistência em um runner de testes JS;
- manter o comportamento externo e a UI do modal sem quebrar o fluxo de sucesso.

Isso seria refatoração fora do escopo solicitado.
